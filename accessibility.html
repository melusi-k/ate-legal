Accessibility Statement

Last updated: 11 October 2026

ate is built to be accessible and easy to use with the default accessibility tools available on iPhone and iPad. This statement explains the steps taken to support screen-reader and low-vision users.

Accessibility features

  • Large, legible UI text and spacing for reading comfort.
  • Support for Dynamic Type, VoiceOver, and default iOS accessibility settings.
  • Dark mode and high-contrast-friendly design choices.
  • Reduced-motion support for users who prefer a calmer interface.
  • Clear focus states and strong button contrast for keyboard and assistive tech users.

Experience design

ate is designed around practical cooking workflows. The app aims to keep important actions obvious: save, edit, scale, cook, and move through recipe steps with minimal friction. Large touch targets are used where possible, with clear labels and semantic structure.

Website accessibility

The public legal site is also designed with accessible HTML structure, adequate color contrast, and responsive layout so it remains usable on mobile and desktop devices.

Known limitations

Because ate is still early-stage and actively evolving, some features may not yet be fully optimised for every assistive tech configuration. The app and legal site will continue to be improved as the product matures.

Feedback

If there is an accessibility issue or a barrier preventing you from using ate, please contact the developer and report it. Feedback is welcome and will be used to improve future releases.
